## 1. 인텐트 분석 (Intent Analysis)

| 항목 | 내용 |
|---|---|
| **User Request** | 디지털 테이블오더 서비스 구축 — 고객용 주문 웹UI + 관리자용 관리 화면 + 서버/DB |
| **Request Type** | New Project (Greenfield) |
| **Scope Estimate** | Multiple Components (고객 웹앱, 관리자 웹앱, 백엔드 API, 데이터 저장소) |
| **Complexity Estimate** | Moderate (다중 사용자 유형, 세션 라이프사이클, 준실시간 모니터링) |
| **Requirements Depth** | Standard |

### 1.1 서비스 비전
디지털 주문 시스템을 통해 고객에게는 편리한 주문 경험을, 매장 운영자에게는 효율적인 운영 환경을 제공하는 테이블오더 플랫폼.

### 1.2 사용자 유형
- **고객(Customer)**: 테이블 태블릿에서 메뉴를 탐색하고 주문하는 매장 방문객
- **관리자(Admin)**: 매장을 운영하며 주문을 모니터링하고 테이블/세션을 관리하는 매장 운영자

### 1.3 멀티테넌시(매장) 범위
- 요구사항 전반에 "매장 식별자"가 사용되므로, **데이터 모델은 다중 매장(멀티테넌트)을 지원하는 구조**로 설계한다. (매장·테이블·메뉴·주문·주문이력은 모두 매장 식별자에 소속)
- 단, **MVP 시연/실행은 단일 매장 시드 데이터**를 기준으로 한다. 다중 매장 등록·관리 UI는 MVP 범위 외이며, 필요 시 seed 데이터에 매장을 추가하여 확장한다.
- 모든 데이터 조회/변경은 인증된 매장 범위 내로 제한된다(테넌트 격리; NFR-S-02 객체 수준 인가와 연계).

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 고객용 기능 (Customer)

**FR-C-01 테이블 태블릿 자동 로그인 및 세션 관리**
- 관리자가 1회 초기 설정: 매장 식별자, 테이블 번호, 테이블 비밀번호 입력 → 로그인 정보 로컬 저장
- 1회 로그인 성공 후 저장된 정보로 자동 로그인
- 테이블 세션은 16시간 유지되며, 관리자의 '이용 완료' 처리 시 종료

**FR-C-02 메뉴 조회 및 탐색**
- 메뉴 화면을 기본 화면으로 항상 표시
- 카테고리별 메뉴 분류/표시, 카테고리 간 빠른 이동
- 메뉴 상세 정보: 메뉴명, 가격, 설명, 이미지
- 메뉴는 고정/시드 데이터로 제공 (MVP)

**FR-C-03 장바구니 관리**
- 메뉴 추가/삭제, 수량 증감, 총 금액 실시간 계산, 장바구니 비우기
- 클라이언트 측 로컬 저장 (페이지 새로고침 시에도 유지)
- 서버 전송은 주문 확정 시에만 수행

**FR-C-04 주문 생성**
- 주문 내역 최종 확인 및 주문 확정
- 주문 성공 시: 주문 번호 표시 → 장바구니 자동 비우기 → (5초 표시 후) 메뉴 화면으로 자동 리다이렉트
- 주문 실패 시: 에러 메시지 표시, 장바구니 유지
- 주문 정보: 매장 식별, 테이블 식별, 메뉴 목록(메뉴명·수량·단가), 총 금액, 세션 ID

**FR-C-05 주문 내역 조회**
- 현재 테이블 세션의 주문만 표시 (이전 세션/이용 완료 주문 제외)
- 주문 시간 순 정렬, 주문별 상세(주문 번호·시각·메뉴/수량·금액·상태) 표시
- 주문 상태(대기중/준비중/완료) 표시, 폴링으로 준실시간 업데이트
- 페이지네이션 또는 무한 스크롤

**FR-C-06 주문 수정 불가**
- 고객은 확정된 주문을 수정하거나 취소할 수 없음 (관리자 직권 삭제만 가능)

### 3.2 관리자용 기능 (Admin)

**FR-A-01 매장 인증**
- 매장 식별자 + 사용자명 + 비밀번호 로그인
- JWT 기반 인증, 16시간 세션 유지, 새로고침 시 세션 유지, 16시간 후 자동 로그아웃

**FR-A-02 준실시간 주문 모니터링**
- 폴링 기반 주문 목록 업데이트 (약 2초 간격, 목표: 2초 이내 표시)
- 그리드/대시보드 레이아웃: 테이블별 카드, 각 카드에 총 주문액 + 최신 주문 3개 미리보기
- 주문 상세: 테이블 번호, 주문 번호, 주문 시각, 메뉴/수량(축약), 총 금액
- 주문 카드 클릭 시 전체 메뉴 목록 상세 보기
- 주문 상태 변경(대기중/준비중/완료)
- 신규 주문 시각적 강조, 테이블별 필터링

**FR-A-03 테이블 관리**
- 테이블 태블릿 초기 설정(테이블 번호·비밀번호, 16시간 세션 생성, 자동 로그인 활성화)
- 주문 삭제(직권 수정): 확인 팝업 → 즉시 삭제 → 테이블 총 주문액 재계산 → 피드백
- 테이블 세션 처리: 세션 시작(첫 주문)/종료(이용 완료) 관리
  - 종료 시 해당 세션 주문을 과거 이력으로 이동
  - 종료 시 현재 주문 목록 및 총 주문액 0으로 리셋
  - 새 고객이 이전 내역 없이 시작 가능
- 과거 주문 내역 조회: 테이블별 과거 주문(시간 역순), 주문 정보 + 이용 완료 시각, 날짜 필터링

**FR-A-04 메뉴 관리 (MVP 범위 외)**
- MVP에서는 고정/시드 메뉴 사용. 관리자 메뉴 CRUD(등록/수정/삭제/순서조정)는 향후 확장 항목.

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 성능
- **NFR-P-01**: 관리자 대시보드는 신규 주문을 약 2초 이내에 표시 (폴링 간격 ~2초)
- **NFR-P-02**: 메뉴 화면 및 주문 화면은 터치 태블릿에서 즉각적으로 반응

### 4.2 사용성 / UX
- **NFR-U-01**: 카드 형태 메뉴 레이아웃, 명확한 시각적 계층 구조
- **NFR-U-02**: 터치 친화적 버튼 크기 (최소 44x44px)
- **NFR-U-03**: 한국어 UI (MVP)

### 4.3 보안 (Security Baseline 적용 — 활성화됨)
- **NFR-S-01 (SECURITY-12)**: 관리자 비밀번호는 bcrypt 등 적응형 알고리즘으로 해싱 저장. 로그인 시도 제한(브루트포스 방지) 적용. 하드코딩 자격증명 금지
- **NFR-S-02 (SECURITY-08)**: JWT 서버 측 검증(서명·만료·발급자)을 모든 요청에서 수행. 기본 거부(deny-by-default), 객체 수준 인가(테이블/주문 소유권 검증으로 IDOR 방지)
- **NFR-S-03 (SECURITY-05)**: 모든 API 파라미터 입력 검증(타입·길이·형식), 파라미터화 쿼리로 SQL 인젝션 방지
- **NFR-S-04 (SECURITY-03)**: 구조화 로깅(타임스탬프·요청 ID·레벨·메시지), 비밀번호/토큰 등 민감정보 로깅 금지
- **NFR-S-05 (SECURITY-04)**: HTML 제공 엔드포인트에 보안 HTTP 헤더 설정(CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy 등)
- **NFR-S-06 (SECURITY-15)**: 모든 외부 호출(DB 등) 명시적 에러 처리, 실패 시 안전하게 닫힘(fail closed), 사용자에게 일반화된 오류 메시지
- **NFR-S-07 (SECURITY-10)**: 의존성 버전 고정(lock 파일), 취약점 스캔 구성
- 나머지 SECURITY 규칙(암호화 at-rest/네트워크 구성/CDN SRI 등)은 로컬 SQLite/로컬 배포 특성상 해당 단계(설계·인프라)에서 적용 가능성 평가 및 N/A 판정 예정

### 4.4 신뢰성 / 데이터
- **NFR-D-01**: 주문 이력은 OrderHistory에 저장, 세션 ID로 그룹화, 이용 완료 시각 기록
- **NFR-D-02**: 테이블 세션 종료 시 현재 주문/총액 리셋, 과거 이력 보존
- **NFR-D-03**: 모든 타임스탬프는 **Asia/Seoul** 타임존 기준으로 기록·표시

### 4.5 테스트 (PBT Partial 적용)
- **NFR-T-01**: 순수 함수 및 직렬화 라운드트립(예: 장바구니 총액 = 항목 단가×수량 합계, 주문 총액 재계산)에 대해 속성 기반 테스트 적용

## 5. 제외 범위 (Out of Scope — constraints.md)

- 결제: 실제 결제/PG 연동/영수증/환불/포인트·쿠폰
- 인증: OAuth·SNS 로그인, 2FA/OTP
- 파일/컨텐츠: 이미지 리사이징·최적화, CMS, 광고
- 알림: 푸시/SMS/이메일/소리·진동 알림
- 주방: 주문 주방 전달, 식재료 재고 관리
- 고급 기능: 데이터 분석/매출 리포트/재고 관리/직원 관리/예약/리뷰/다국어
- 외부 연동: 배달 플랫폼/POS/소셜 공유/지도/번역 API

## 6. MVP 개발 범위 (요약)

**고객용**: 테이블 태블릿 자동 로그인·세션 관리, 메뉴 조회, 장바구니 관리, 주문 생성(성공 후 자동 리다이렉트), 주문 내역 조회(현재 세션만)

**관리자용**: 매장 인증(16시간 세션), 준실시간 주문 모니터링(그리드 레이아웃, 폴링), 테이블 관리(초기 설정·주문 삭제·이용 완료·과거 내역 조회)

## 7. 용어 정의

- **테이블 세션**: 특정 테이블에 고객이 앉아 첫 주문을 시작한 시점부터 해당 테이블 '이용 완료' 처리까지의 기간. 종료 후 다른 고객의 첫 주문 시작 시 새 세션 시작.
- **MVP**: 최소 기능 제품
- **폴링(Polling)**: 클라이언트가 주기적으로 서버에 상태를 요청하여 갱신하는 방식

---

## 8. 핵심 요구사항 요약

- 두 개의 웹 프론트엔드(고객용/관리자용, React+TS)와 FastAPI 백엔드, SQLite 저장소로 구성된 테이블오더 시스템
- 태블릿 사전 설정 기반 고객 자동 로그인과 16시간 테이블 세션 라이프사이클이 핵심
- 관리자 대시보드는 폴링으로 준실시간(약 2초) 주문 모니터링 제공
- 보안 베이스라인 전면 적용(JWT·bcrypt·입력 검증·인가·로깅), PBT는 금액 계산 등 순수 로직에 부분 적용
- 결제·알림·주방·외부 연동 등은 명시적으로 제외

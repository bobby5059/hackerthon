# 사용자 스토리 (User Stories) — 테이블오더 서비스

**조직 방식**: Epic 기반(Hybrid) — 페르소나별 에픽 아래 기능 스토리 계층 구성
**인수 조건 형식**: Given/When/Then
**세분화**: fine-grained (INVEST 준수)
**우선순위**: MoSCoW (Must / Should / Could / Won't) + MVP 표기

> 스토리 형식: **As a** \<페르소나\>, **I want** \<목표\>, **so that** \<가치\>

---

# 페르소나 A: 고객 (Customer)

## EPIC C1 — 테이블 인증 및 세션 (자동 로그인)

### C1-S1 태블릿 자동 로그인 (Must, MVP)
**As a** 고객, **I want** 자리에 앉아 태블릿을 켜면 별도 로그인 없이 바로 주문 화면을 보고 싶다, **so that** 대기 없이 즉시 주문할 수 있다.

**Acceptance Criteria**
- Given 관리자가 이미 태블릿에 매장 식별자·테이블 번호·테이블 비밀번호를 설정했고 유효한 테이블 세션이 있는 상태에서, When 고객이 태블릿(브라우저)을 열면, Then 저장된 정보로 자동 로그인되어 메뉴 화면이 표시된다.
- Given 저장된 테이블 세션이 16시간을 초과했거나 관리자가 이용 완료 처리했을 때, When 태블릿을 열면, Then 자동 로그인이 되지 않고 관리자 재설정이 필요함을 안내한다.
- Given 자동 로그인 상태에서, When 페이지를 새로고침하면, Then 세션이 유지되어 다시 로그인 화면으로 돌아가지 않는다.

### C1-S2 현재 테이블 세션 컨텍스트 유지 (Must, MVP)
**As a** 고객, **I want** 내 주문이 현재 테이블 세션에만 연결되기를 원한다, **so that** 이전 손님의 주문과 섞이지 않는다.

**Acceptance Criteria**
- Given 유효한 테이블 세션(세션 ID 보유) 상태에서, When 고객이 주문/조회를 수행하면, Then 모든 요청은 현재 세션 ID 및 매장·테이블 범위로 처리된다.
- Given 관리자가 해당 테이블을 이용 완료 처리한 뒤, When 새 고객이 첫 주문을 시작하면, Then 새 세션 ID가 생성되고 이전 세션 데이터는 조회되지 않는다.

## EPIC C2 — 메뉴 조회 및 탐색

### C2-S1 카테고리별 메뉴 조회 (Must, MVP)
**As a** 고객, **I want** 카테고리별로 정리된 메뉴를 보고 싶다, **so that** 원하는 메뉴를 쉽게 찾을 수 있다.

**Acceptance Criteria**
- Given 메뉴 화면이 기본 화면으로 표시된 상태에서, When 고객이 화면을 열면, Then 카테고리와 각 메뉴가 카드 형태로 표시된다.
- Given 여러 카테고리가 있을 때, When 고객이 카테고리를 선택하면, Then 해당 카테고리 메뉴로 빠르게 이동한다.
- Given 각 메뉴 카드에는, Then 메뉴명·가격(원, 정수)·설명·이미지가 표시된다.

### C2-S2 메뉴 상세 정보 확인 (Should, MVP)
**As a** 고객, **I want** 메뉴의 상세 정보를 확인하고 싶다, **so that** 무엇을 주문할지 결정할 수 있다.

**Acceptance Criteria**
- Given 메뉴 카드가 표시된 상태에서, When 고객이 메뉴를 선택하면, Then 메뉴명·가격·설명·이미지 상세가 표시된다.
- Given 이미지 URL이 유효하지 않을 때, When 상세를 표시하면, Then 대체 표시(플레이스홀더)로 화면이 깨지지 않는다.

### C2-S3 터치 친화적 UI (Should, MVP)
**As a** 고객, **I want** 큰 버튼과 명확한 레이아웃을 원한다, **so that** 터치 태블릿에서 실수 없이 조작할 수 있다.

**Acceptance Criteria**
- Given 태블릿 화면에서, Then 터치 대상(버튼)은 최소 44x44px 이상이다.
- Given 화면 구성은, Then 명확한 시각적 계층(카테고리 > 메뉴 카드 > 담기 버튼)을 가진다.

## EPIC C3 — 장바구니 관리

### C3-S1 장바구니 담기/수량 조절 (Must, MVP)
**As a** 고객, **I want** 메뉴를 장바구니에 담고 수량을 조절하고 싶다, **so that** 주문 전에 선택을 구성할 수 있다.

**Acceptance Criteria**
- Given 메뉴 화면에서, When 고객이 '담기'를 누르면, Then 해당 메뉴가 장바구니에 추가된다.
- Given 장바구니에 항목이 있을 때, When 수량 증가/감소를 누르면, Then 수량이 갱신되고 총 금액이 실시간으로 재계산된다.
- Given 수량이 1인 항목에서, When 감소를 누르면, Then 항목이 장바구니에서 제거된다(또는 0으로 두지 않음).

### C3-S2 장바구니 로컬 유지 (Must, MVP)
**As a** 고객, **I want** 새로고침해도 장바구니가 유지되기를 원한다, **so that** 실수로 담은 내용을 잃지 않는다.

**Acceptance Criteria**
- Given 장바구니에 항목이 담긴 상태에서, When 페이지를 새로고침하면, Then 장바구니 내용과 수량이 그대로 유지된다(클라이언트 로컬 저장).
- Given 주문이 확정되기 전에는, Then 장바구니 데이터는 서버로 전송되지 않는다.

### C3-S3 장바구니 비우기 (Should, MVP)
**As a** 고객, **I want** 장바구니를 한 번에 비우고 싶다, **so that** 처음부터 다시 담을 수 있다.

**Acceptance Criteria**
- Given 장바구니에 항목이 있을 때, When '비우기'를 누르면, Then 모든 항목이 제거되고 총 금액이 0이 된다.

---

## EPIC C4 — 주문 생성

### C4-S1 주문 확정 (Must, MVP)
**As a** 고객, **I want** 장바구니 내용을 주문으로 확정하고 싶다, **so that** 실제로 음식을 받을 수 있다.

**Acceptance Criteria**
- Given 장바구니에 1개 이상 항목이 있을 때, When 고객이 주문 내역을 확인하고 '주문 확정'을 누르면, Then 주문이 서버에 생성되고(매장·테이블·세션 ID·메뉴 목록·총액 포함) 성공 응답을 받는다.
- Given 장바구니가 비어 있을 때, When '주문 확정'을 누르면, Then 주문이 생성되지 않고 안내 메시지가 표시된다.
- Given 주문 생성 요청 시, Then 총액은 서버에서 Σ(단가×수량)로 재검증된다.

### C4-S2 주문 성공 플로우 (Must, MVP)
**As a** 고객, **I want** 주문이 성공하면 주문 번호를 확인하고 자동으로 메뉴로 돌아가고 싶다, **so that** 주문 접수를 확신하고 다음 행동을 할 수 있다.

**Acceptance Criteria**
- Given 주문이 성공했을 때, When 성공 화면이 표시되면, Then 주문 번호가 표시되고 장바구니가 자동으로 비워진다.
- Given 주문 성공 화면 표시 후, When 약 5초가 지나면, Then 자동으로 메뉴 화면으로 리다이렉트된다.

### C4-S3 주문 실패 처리 (Must, MVP)
**As a** 고객, **I want** 주문이 실패하면 명확한 안내와 함께 장바구니가 유지되기를 원한다, **so that** 다시 시도할 수 있다.

**Acceptance Criteria**
- Given 주문 요청이 실패했을 때(네트워크/서버 오류), When 응답을 받으면, Then 에러 메시지가 표시되고 장바구니 내용은 유지된다.
- Given 실패한 주문은, Then 서버에 생성되지 않는다(fail closed).

### C4-S4 주문 수정/취소 불가 (Won't for MVP)
**As a** 고객, **I want** (참고) 확정된 주문은 내가 수정/취소할 수 없음을 이해한다, **so that** 정정은 직원(관리자)에게 요청한다.

**Acceptance Criteria**
- Given 주문이 확정된 후, When 고객이 수정/취소를 시도할 경로는, Then 제공되지 않는다(관리자 직권 삭제만 가능).

---

## EPIC C5 — 주문 내역 조회

### C5-S1 현재 세션 주문 내역 조회 (Must, MVP)
**As a** 고객, **I want** 현재 테이블 세션의 주문 내역을 보고 싶다, **so that** 무엇을 주문했는지, 상태가 어떤지 확인할 수 있다.

**Acceptance Criteria**
- Given 현재 세션에 주문이 있을 때, When 고객이 주문 내역을 열면, Then 주문 시간 순으로 정렬되어 주문 번호·시각·메뉴/수량·금액·상태(대기중/준비중/완료)가 표시된다.
- Given 이전 세션이나 이용 완료된 주문은, Then 목록에 표시되지 않는다.
- Given 주문이 많을 때, Then 페이지네이션 또는 무한 스크롤로 표시된다.

### C5-S2 주문 상태 준실시간 갱신 (Should, MVP)
**As a** 고객, **I want** 주문 상태가 자동으로 갱신되기를 원한다, **so that** 준비 상황을 알 수 있다.

**Acceptance Criteria**
- Given 주문 내역 화면이 열린 상태에서, When 관리자가 상태를 변경하면, Then 폴링 주기(약 2초) 내에 고객 화면의 상태 표시가 갱신된다.

# 페르소나 B: 관리자 (Admin)

## EPIC A1 — 매장 인증

### A1-S1 매장 로그인 (Must, MVP)
**As a** 관리자, **I want** 매장 식별자·사용자명·비밀번호로 로그인하고 싶다, **so that** 내 매장 관리 화면에 접근할 수 있다.

**Acceptance Criteria**
- Given 유효한 매장 자격증명으로, When 관리자가 로그인하면, Then JWT가 발급되고 대시보드로 진입한다.
- Given 잘못된 자격증명으로, When 로그인하면, Then 일반화된 오류 메시지가 표시되고 접근이 거부된다(fail closed).
- Given 비밀번호는, Then bcrypt 등 적응형 해시로 저장되며 평문/로그에 노출되지 않는다.

### A1-S2 16시간 세션 유지 및 자동 로그아웃 (Must, MVP)
**As a** 관리자, **I want** 세션이 16시간 유지되고 이후 자동 로그아웃되기를 원한다, **so that** 근무 중 재로그인 없이 안전하게 사용할 수 있다.

**Acceptance Criteria**
- Given 로그인 상태에서, When 브라우저를 새로고침하면, Then 세션이 유지된다.
- Given 로그인 후 16시간이 경과하면, When 요청을 보내면, Then 토큰이 만료되어 자동 로그아웃되고 재로그인을 요구한다.
- Given 모든 보호된 요청은, Then 서버 측에서 JWT(서명·만료·발급자)를 검증한다.

### A1-S3 로그인 시도 제한 (Should, MVP)
**As a** 관리자(시스템), **I want** 반복 로그인 실패 시 제한이 걸리기를 원한다, **so that** 무차별 대입 공격을 방지한다.

**Acceptance Criteria**
- Given 동일 계정에 대해 지정 횟수 이상 로그인 실패가 발생하면, When 추가 시도가 오면, Then 계정 잠금/지연 등 제한이 적용되고 관련 보안 이벤트가 로깅된다.

## EPIC A2 — 준실시간 주문 모니터링

### A2-S1 테이블별 그리드 대시보드 (Must, MVP)
**As a** 관리자, **I want** 테이블별 카드 그리드로 주문을 한눈에 보고 싶다, **so that** 여러 테이블을 동시에 관리할 수 있다.

**Acceptance Criteria**
- Given 대시보드가 열린 상태에서, Then 각 테이블은 카드로 표시되며 카드에는 총 주문액과 최신 주문 3개 미리보기가 표시된다.
- Given 각 주문 미리보기에는, Then 테이블 번호·주문 번호·주문 시각·메뉴/수량(축약)·총 금액이 표시된다.

### A2-S2 폴링 기반 준실시간 갱신 (Must, MVP)
**As a** 관리자, **I want** 신규 주문이 자동으로 화면에 나타나기를 원한다, **so that** 주문을 놓치지 않는다.

**Acceptance Criteria**
- Given 대시보드가 열린 상태에서, When 신규 주문이 생성되면, Then 폴링 주기(약 2초) 내에 대시보드에 표시된다(목표: 2초 이내).
- Given 신규 주문이 나타날 때, Then 색상 변경/애니메이션 등으로 시각적으로 강조된다.

### A2-S3 주문 상세 보기 (Should, MVP)
**As a** 관리자, **I want** 주문 카드를 눌러 전체 메뉴 목록을 보고 싶다, **so that** 상세 내용을 확인할 수 있다.

**Acceptance Criteria**
- Given 주문 카드가 표시된 상태에서, When 관리자가 카드를 클릭하면, Then 해당 주문의 전체 메뉴 목록과 상세가 표시된다.

### A2-S4 주문 상태 변경 (Must, MVP)
**As a** 관리자, **I want** 주문 상태를 대기중/준비중/완료로 바꾸고 싶다, **so that** 조리 진행을 관리할 수 있다.

**Acceptance Criteria**
- Given 주문이 표시된 상태에서, When 관리자가 상태를 변경하면, Then 상태가 저장되고 폴링 주기 내에 고객·대시보드 화면에 반영된다.
- Given 상태 변경은, Then 인증된 매장 범위 내 주문에 대해서만 허용된다(테넌트 격리/인가).

### A2-S5 테이블별 필터링 (Could, MVP)
**As a** 관리자, **I want** 특정 테이블만 필터링하고 싶다, **so that** 특정 테이블에 집중할 수 있다.

**Acceptance Criteria**
- Given 여러 테이블 주문이 있을 때, When 관리자가 테이블 필터를 선택하면, Then 해당 테이블 주문만 표시된다.

## EPIC A3 — 테이블 관리 및 세션 라이프사이클

### A3-S1 테이블 태블릿 초기 설정 (Must, MVP)
**As a** 관리자, **I want** 테이블 태블릿에 번호와 비밀번호를 설정하고 싶다, **so that** 해당 태블릿이 자동 로그인으로 동작한다.

**Acceptance Criteria**
- Given 신규 테이블 태블릿에서, When 관리자가 테이블 번호·비밀번호를 입력해 설정하면, Then 16시간 테이블 세션이 생성되고 자동 로그인이 활성화된다.
- Given 입력값 검증에서, Then 필수 필드 누락/형식 오류 시 저장되지 않고 오류가 안내된다.

### A3-S2 주문 삭제 (직권 수정) (Must, MVP)
**As a** 관리자, **I want** 잘못된 주문을 삭제하고 싶다, **so that** 주문 내역을 정정할 수 있다.

**Acceptance Criteria**
- Given 특정 주문에 대해, When 관리자가 삭제를 누르면, Then 확인 팝업이 표시된다.
- Given 확인 팝업에서, When 삭제를 승인하면, Then 주문이 즉시 삭제되고 테이블 총 주문액이 재계산되며 성공 피드백이 표시된다.
- Given 삭제 작업은, Then 인증된 매장 범위 내에서만 허용되고 감사 가능하도록 로깅된다(누가/언제/무엇).

### A3-S3 테이블 이용 완료(세션 종료) 처리 (Must, MVP)
**As a** 관리자, **I want** 손님이 떠난 테이블을 이용 완료 처리하고 싶다, **so that** 새 손님이 이전 주문 없이 시작할 수 있다.

**Acceptance Criteria**
- Given 진행 중인 테이블 세션에서, When 관리자가 '이용 완료'를 누르면, Then 확인 팝업이 표시된다.
- Given 확인 시, Then 해당 세션의 주문 내역이 과거 이력(OrderHistory)으로 이동하고 완료 시각이 기록된다.
- Given 이용 완료 후, Then 테이블의 현재 주문 목록과 총 주문액이 0으로 리셋된다.
- Given 이용 완료 후 새 고객이 첫 주문을 시작하면, Then 새 세션 ID로 시작되며 이전 주문은 현재 목록에 표시되지 않는다.

### A3-S4 과거 주문 내역 조회 (Should, MVP)
**As a** 관리자, **I want** 테이블별 과거 주문 내역을 조회하고 싶다, **so that** 지난 이용 기록을 확인할 수 있다.

**Acceptance Criteria**
- Given 과거 이력이 있을 때, When 관리자가 '과거 내역'을 열면, Then 테이블별 과거 주문이 시간 역순으로 표시된다(주문 번호·시각·메뉴 목록·총액·이용 완료 시각).
- Given 과거 내역 화면에서, When 날짜 필터를 적용하면, Then 해당 기간의 주문만 표시된다.
- Given '닫기'를 누르면, Then 대시보드로 복귀한다.

# INVEST 준수 확인

- **Independent**: 각 스토리는 독립 구현/검증 가능하도록 fine-grained로 분해
- **Negotiable**: 구현 방식은 이후 설계 단계에서 협의(스토리는 목표/가치에 집중)
- **Valuable**: 각 스토리는 고객 또는 관리자에게 명확한 가치 제공
- **Estimable**: 범위가 좁아 추정 가능
- **Small**: MVP 스토리는 단일 기능 단위
- **Testable**: 모든 스토리에 Given/When/Then 인수 조건 포함
